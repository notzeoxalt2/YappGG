# YappGG 0.4.2 — October 4, 2026

Per the user's final direction, use the recovered GG 120 microphone renderer and preset header directly, with red accents and the supplied YappGG identity. Original effect spacing, preset tile alignment, menu buttons, waveform, graph sizing, disabled states and typography remain owned by the original components. The horizontal microphone source/fader/apps strip remains as previously requested. Only the standalone shell, settings and sidebar-free modal offsets need local CSS.

Removed the global border-box rule that shrank the original slider labels and caused handle overlap. Removed the replacement preset header and decorative raster waveform. Retain graph response-cache and immediate-paint corrections, and the standalone library's available-height correction. Verification compares all ten original filter responses, checks rendered graph pixels after resizing, exercises preset CRUD and checks slider label/track/value separation.

Logo exports come from `tools/create_brand.py`, one vector construction with simplified optical drawing at 16–24 pixels. App ICO includes individual native-resolution PNG frames from 16 to 256 pixels. Tray light/dark ICO files include 16, 20, 24, 32, 40 and 48-pixel frames. Electron chooses tray contrast from the Windows system theme and updates it when the theme changes. AppUserModelId is explicitly local.yappgg.mic. Large vector marks and horizontal/stacked lockups remain available.

Packaged preferences migrate from YappEQ or Sonar Mic into YappGG. The release runs a direct local native microphone engine with bundled Sonar audio components, without requiring the GG application or service. It uses the existing signed driver, installing the bundled unchanged driver components if missing. This is not a newly signed YappGG driver. Windows policy renames the capture endpoint to YappGG Microphone, with YappGG Audio as its adapter label.

If a user already runs GG, compatibility mode controls its local microphone API instead of creating a competing engine. Without GG, local processing uses the bundled native API and APO. Speaker-copy output is muted with no destination. Direct capture tests with processing bypassed proved nonzero transport and digital silence on mute; ClearCast configuration readback passed. The user confirmed that remote listeners no longer hear voice through screen share while Discord is muted. Native session readback shows the Discord render session muted and the microphone producer unmuted. Voice quality beyond transport and mute still requires subjective testing.

The installer offers startup enabled by default and optional Windows default microphone setup for Discord. It does not overwrite an explicitly selected Discord device. Settings includes both controls plus Reduce memory in tray, which unloads the settings renderer while preserving host-owned processing and reloads it on reopening. No VB-CABLE is included. The custom driver prototype remains development-only and requires signing.

The browser's cloned toolbar uses the base toolbar's actual position and width, excluding the scroll gutter. Its height is the remaining viewport height. The underlying toolbar is hidden only while the cloned one is visible, preventing the doubled TEST box. Verification checks matching left/width, hidden underlying header and viewport bounds.

Twelve additional built-in presets are generated by `host/extra-presets.cjs`: Clear Voice, Crisp Speech, Warm Studio, Smooth Broadcast, Bass Monster, Megaphone, Tin Can, Lo-Fi Telephone, Loud Mess, Crappy Voice, Busted Radio and Midnight Radio. They use distinct 10-band EQ curves and existing noise cancellation/compression settings. Gates default off to avoid intentionally cutting quiet speech. Crappy Voice, Loud Mess, Busted Radio, Megaphone, Tin Can and Lo-Fi Telephone use the local FunMicrophone pipeline: band limiting, original EQ filters, hard clipping, sample-and-hold and bit-depth reduction. Clean profiles continue to use the native ClearCast path. Existing built-in fun profiles migrate their effect metadata while preserving saved EQ changes. There is no pitch-shifting claim. Stable IDs make migration idempotent and preserve saved selections, edits and favorites.

Screen-share protection checks the virtual microphone render sessions once per second and mutes Discord, DiscordPTB and DiscordCanary sessions, leaving the native producer and physical playback alone. The separate desktop audio switch blocks other apps injected into that virtual mic; it does not perform acoustic echo cancellation. Original session mute states are restored when disabling protection or closing the backend. Settings exposes a 0–36 dB boost slider and numeric gain up to 120 dB, applied after the normal level control. An actual WASAPI render fixture verifies injection blocking and restoration; native gain readback verifies +6 dB.

Startup creates the window before routing setup and returns cached physical devices without awaiting an audio executable. Discovery and engine startup continue in the background; first-launch controls say Finding microphone until discovery finishes. Device queries share a pending operation and use a short cache. Startup diagnostics measured the rendered UI around 1.1 seconds in the normal local run. A recording-state event before renderer initialization no longer dereferences a missing reducer branch.

0.4.2 adds an independently selected, opt-in aftereffect in Settings. Standard microphone APO processing runs on stereo buffers before local degradation and boost. Capture-specific EQ controls are mirrored from the base preset; a synthetic 1 kHz test verifies a +12 dB change produces a 3.981 ratio. Backend tests verify ClearCast stays enabled, the mirrored base EQ, +36 dB gain, digital silence on mute and restoration. Capture buffering uses 20 ms event-driven input rather than 100 ms defaults.

Renderer CSS is reduced from 12.56 MB to 0.716 MB without the duplicate stylesheet link; approximately 66.8 MB of unreferenced root-level image/font assets are excluded from release packaging. Retain shared scripts, referenced fonts, signed driver files, AI runtimes and legal notices. The current signed driver needs its render feed active; Windows still exposes this internal output. Disabling it invalidates transport.

Final startup fix disables Chromium background throttling so a covered window does not defer its initial UI/graph paint. Startup registration is applied after ui-ready and the UI uses the saved startup preference. A normal development launch rendered at 670 ms. Any positive boost uses the in-memory APO pipeline: the native stream mixer accepts normalized gain only, so passing >1 there could produce 0x80070057. Microsoft-signed app-local C++ runtime DLLs are included for PCs without the prerequisite.
`nAudio recovery: lost Windows audio COM connections (including RPC_E_SERVER_DIED_DNE) recreate the backend, refresh device handles, and restore the selected base preset, aftereffect, boost and isolation. Three bounded retries; Stop cancels pending recovery. Technical failure details remain in host.log.

Soundboard: async sequential Store/Deflate ZIP import with CRC checks and range reads; Windows Media Foundation decoder with isolated Chromium fallback. Sources normalize to mono float WAV for low-latency streaming; no FFmpeg redistribution or user media in the installer. Mixing happens after ClearCast/voice aftereffects and before the final shared mute and limiter. Per-clip volume is independent of microphone boost. Shortcut registrations persist in a separate sound library and coexist with the voice-effect shortcut. Original 30 non-reserved SVG preset illustrations restored, with the reserved logo retaining YappGG.
